## 1. Contexto / Motivação

Até aqui, Prolog só **prova** coisas (verdadeiro/falso) — ele não calcula. Mas a maioria dos
programas precisa fazer **contas**. O problema: como um paradigma lógico, baseado em
unificação, faz aritmética? A resposta é o operador `is/2`, que **avalia** uma expressão
aritmética e **ata** o resultado a uma variável. Esta aula apresenta os operadores, a
precedência, as funções aritméticas e como lidar com predicados que têm **mais de uma
semântica** (funcionam "nas duas direções").

---

## 2. Predicado `is/2`

O predicado extra-lógico `is/2` é usado para **computar expressões aritméticas**:

```prolog
Number is Expr.
```

- O resultado da expressão `Expr` é **atado** à variável `Number`.
- **Parênteses** podem ser usados para evitar ambiguidades e alterar a ordem de precedência.

```prolog
% nativo: não precisa carregar arquivo
?- X is 1 + 2 * 3.
X = 7.

?- X is (1 + 2) * 3.
X = 9.

?- X is 2 / 5.
X = 0.4.

?- X is 2 - 5.
X = -3.

?- X is 2 ^ 5.
X = 32.

?- X is 20 // 3.
X = 6.
```

## 3. Operadores

**Operadores** são predicados que suportam, além da pré-fixada padrão, as notações
**infixada** ou **pós-fixada**. Novos operadores são declarados com a diretiva `op/3`:

```prolog
:- op(Precedence, Type, Name).
```

- `Name` = átomo que nomeia o operador; `Precedence` = inteiro entre 0 e 1200 —
  **quanto menor o valor, maior a precedência**.
- `Type` = átomo com os caracteres `x`, `y` e `f`, que determina a **posição** do operador
  (indicada por `f`) e a **associatividade** (posição de `y`).
  - `xfy` → binário, infixado, **associativo à direita**.
  - `xf` → unário, **pós-fixado**.
  - `yfx` → associativo à esquerda (aritmética usual).
- Precedência `0` **apaga** a declaração do operador.
- O tipo/precedência de um operador pré-definido pode ser consultado com `current_op/3`:

```prolog
current_op(Precedence, Type, Name).
```

> Detalhe já visto na aula 01: `,` é `1000 xfy`, `;` é `1100 xfy`, `\+` é `900 fy`.

## 4. Operadores aritméticos e relacionais

### Aritméticos

| Operador | Tipo | Precedência | Descrição |
|---|---|---|---|
| `+/2` | yfx | 500 | Adição |
| `-/2` | yfx | 500 | Subtração |
| `*/2` | yfx | 400 | Multiplicação |
| `//2` | yfx | 400 | Divisão nos reais |
| `div/2` | yfx | 400 | Quociente da divisão inteira |
| `mod/2` | yfx | 400 | Resto euclidiano da divisão inteira |
| `^/2` | xfy | 200 | Potência (`a ^ b` = $a^b$) |

Exemplo de regra com expressões (convenção: **o valor de retorno é o último parâmetro**):

```prolog
% salve as regras acima em aritmetica.pl e rode: ?- consult('aritmetica.pl').
number_of_lines(N, Res) :- Res is 2^N.

juros_simples(M, J, T, Res) :- Res is M * (1 + J * T).
juros_compostos(M, J, T, Res) :- Res is M * (1 + J) ** T.

?- number_of_lines(3, N).
N = 8.

?- juros_simples(100, 0.12, 24, Res).
Res = 388.0.
```

### Relacionais

| Operador | Tipo | Precedência | Descrição |
|---|---|---|---|
| `>/2` | xfx | 700 | Maior que |
| `</2` | xfx | 700 | Menor que |
| `>=/2` | xfx | 700 | Maior ou igual |
| `=</2` | xfx | 700 | Menor ou igual |
| `=:=/2` | xfx | 700 | Igual (valor) |
| `=\=/2` | xfx | 700 | Diferente (valor) |

Exemplo — raízes reais de $ax^2+bx+c$:

```prolog
% regra e root_signal em codes/roots.pl: ?- consult('codes/roots.pl').
roots(A, B, C, X) :-
    A =\= 0,
    Delta is B^2 - 4*A*C,
    S is root_signal(Delta),
    X is (-B + S*sqrt(Delta))/(2*A).
```

**Passo a passo — `?- roots(1, -5, 6, X).`** (cada `is` avalia uma conta):

```prolog
A = 1, B = -5, C = 6
Delta is B^2 - 4*A*C      = (-5)^2 - 4*1*6 = 25 - 24 = 1
S is root_signal(Delta)   = root_signal(1) = 1          % Delta >= 0
X is (-B + S*sqrt(Delta))/(2*A) = (5 + 1*1) / 2 = 6/2 = 3.0

?- roots(1, -5, 6, X).
X = 3.0.
```

## 5. Funções aritméticas

Os operadores aritméticos são chamados **funções aritméticas**, pois **"retornam"** o valor
de suas operações (em vez de apenas atá-los a uma variável). Para tornar um **predicado
próprio** em função aritmética:

1. Carregar a biblioteca de aritmética: `:- use_module(library(arithmetic)).`
2. Declarar o predicado como função aritmética com a diretiva `arithmetic_function`.
3. A variável a ser "retornada" deve ser a **última** dos argumentos, e a aridade declarada
   é uma **unidade menor** que a aridade do predicado.

```prolog
% salve em arit.pl e rode: ?- consult('arit.pl').  (diretivas só valem em arquivo;
% depois, a consulta abaixo funciona no listener)
:- use_module(library(arithmetic)).
:- arithmetic_function(number_of_lines/1).

number_of_lines(N, Res) :- Res is 2^N.

?- X is 1 + number_of_lines(4).
X = 17.
```

## 6. Predicados com múltiplas semânticas

Alguns predicados podem ter **mais de uma semântica**. Ex.: `succ/2` serve para **sucessor**
e **antecessor**:

```prolog
% nativo: não precisa carregar arquivo
?- succ(2, S).
S = 3.

?- succ(A, 2).
A = 1.
```

### Exemplos simples para visualizar — `between/3`

`between/3` é um **gerador** de inteiros (nativo da biblioteca): `between(A, B, X)` dá todos os
`X` de `A` a `B`, um por vez.

**Sem `;` → só o 1º:**

```prolog
% nativo: não precisa carregar arquivo
?- between(1, 5, X).
X = 1.
```

**Com `;` → vem o resto (o `between` gera os números via backtracking):**

```prolog
?- between(1, 5, X).
X = 1 ;
X = 2 ;
X = 3 ;
X = 4 ;
X = 5.
```

**Consulta composta (com `,`) → o `between` gera e o 2º objetivo filtra, sozinho:**

```prolog
?- between(1, 10, X), 0 =:= X mod 2.
X = 2 ;
X = 4 ;
X = 6 ;
X = 8 ;
X = 10.
```

> Mesma mecânica do exemplo `cor/1` da aula 03: cada `;` = `redo` no último objetivo.

É possível implementá-los com **condicionais** e predicados extra-lógicos que verificam o
tipo de um termo:

- `var/1` — verdadeiro se a variável é **livre** (ainda não atada).
- `nonvar/1` — verdadeiro se a variável já foi **atada**.
- `integer/1`, `number/1`, `atom/1` — confirmam o **tipo** do termo.

Exemplo — conversão Celsius/Fahrenheit em ambas as direções:

```prolog
% cláusulas em codes/celsius.pl (salve sem as linhas ?-, que são exemplos, e consulte)
celsius_fahrenheit(C, F) :-
    ((var(C), var(F))
        -> instantiation_error('Ao menos uma variável deve estar atada') ; true),
    (nonvar(C) -> F is C*9/5 + 32 ; C is (F - 32)*5/9).

?- celsius_fahrenheit(40, F).
F = 104.

?- celsius_fahrenheit(C, 104).
C = 40.

?- celsius_fahrenheit(100, 100).
false.
```

Outro exemplo — resolver um **Sudoku 4x4** com permutações e comparações:

```prolog
% cláusulas em codes/sudoku.pl: ?- consult('codes/sudoku.pl').
permutation(A, B, C, D) :-
    between(1, 4, A), between(1, 4, B),
    between(1, 4, C), between(1, 4, D),
    A =\= B, A =\= C, A =\= D,
    B =\= C, B =\= D, C =\= D.
```

### Como executar e testar (entradas e saídas verificadas)

Consultas diretas no listener (para `is/2`, os built-ins bastam):

```prolog
% nativo: não precisa carregar arquivo
?- X is 1 + 2 * 3.
X = 7.                    % * (400) liga mais forte que + (500)
?- X is (1 + 2) * 3.
X = 9.                    % parenteses mudam a ordem
?- X is 20 // 3.
X = 6.
?- X is 2 / 5.
X = 0.4.
?- X is 2 ^ 5.
X = 32.
```

Arquivos carregáveis:

```prolog
?- consult('codes/roots.pl').
true.
?- roots(1, -5, 6, X).
X = 3.0.                  % Delta > 0: apenas a raiz com sinal + (ver observacao)
?- roots(1, 0, 1, X).
false.                    % Delta < 0 → falha

?- consult('codes/sudoku.pl').
true.
?- solve_constrained.     % imprime o problema e a solucao 4x4
...
?- solve_open.
...
```

> **`arithmetic_function/1`** (em `user_arithmetic_function.pl`) só expande em cláusula
> **compilada** ou no **toplevel** — por isso as diretivas `?- X is number_of_lines(4).` dão
> erro na carga. No listener funciona: `?- X is 1 + number_of_lines(4).` → `X = 17.`
> **Transcrições** (não carregam; rode à mão): `is.pl`, `succ1.pl`, `succ2.pl`, `expr.pl`,
> `celsius.pl`, `user_arithmetic_function.pl`. Ex.: `?- succ(2, S).` → `S = 3.`;
> `?- celsius_fahrenheit(40, F).` → `F = 104.`; `?- celsius_fahrenheit(100, 100).` → `false.`
