## 1. Contexto / Motivação

Quando você pergunta algo ao Prolog e há **mais de uma resposta possível**, o interpretador
retorna a primeira e para. O **backtracking** é o mecanismo que permite "voltar" e continuar
a busca por outras respostas — é o que torna a programação lógica capaz de **enumerar**
soluções em vez de só responder sim/não. Sem ele, uma consulta teria no máximo uma resposta,
e programas como "liste todos os estudantes da UnB" não funcionariam.

---

## 2. Definição

Quando Prolog tenta satisfazer um objetivo sobre um predicado:

1. Ele percorre **todas as cláusulas** que definem o predicado.
2. Se o objetivo e uma cláusula **unificam**, ela satisfaz o objetivo e é **marcada**.
3. O interpretador retorna os valores **atados** (se há variáveis) ou apenas `true`
   (se todos os argumentos são constantes).
4. Se o usuário solicitar com o **ponto-e-vírgula**, ele **retoma a busca** entre as
   cláusulas a partir da última marcação, **desatando** as variáveis previamente atadas.

Esse processo é o **backtracking**.

---

## 3. Objetivos e fluxo de controle

Um objetivo tem **quatro portas** que representam o fluxo de controle de sua avaliação:

| Porta | Momento |
|---|---|
| **call** | Início da avaliação do objetivo |
| **exit** | Alguma cláusula unificou — termina, atando as variáveis |
| **fail** | Nenhuma cláusula unificou — a avaliação falha |
| **redo** | Após sucesso, o usuário digitou `;` — retoma do ponto parado, desatando variáveis |

```
            call ──► ┌──────────┐ ──► exit
                      │ Objetivo │
            fail ◄── └──────────┘ ◄── redo
```

O fluxo **entra** por `call` e **sai** por `exit` (sucesso) ou `fail` (falha). Ao pedir mais
respostas, reentra-se por `redo`.

### Exemplos simples para visualizar

Base minúscula (salve em `cores.pl` e rode `?- consult('cores.pl').`):

```prolog
cor(vermelho).
cor(azul).
cor(verde).
```

**Sem `;` → só a 1ª solução** (o Prolog para, não há backtracking):

```prolog
?- cor(X).
X = vermelho.
```

**Com `;` → você força o `redo` e vêm as próximas:**

```prolog
?- cor(X).
X = vermelho ;     % você digita ;
X = azul ;         % você digita ;
X = verde.         % última; se digitar ; de novo -> false.
```

As mesmas 4 portas, passo a passo:

```prolog
call cor(X)  → exit X = vermelho     (você digita ;)
redo cor(X)  → exit X = azul         (você digita ;)
redo cor(X)  → exit X = verde        (você digita ;)
redo cor(X)  → fail                  (acabaram as cláusulas)
```

**Consulta composta (com `,`) → o backtracking acontece sozinho**, sem digitar `;`
(salve em `familia.pl` e `?- consult('familia.pl').`):

```prolog
pai(joao, maria).   pai(joao, pedro).   pai(jose, ana).
mulher(maria).      mulher(ana).

?- pai(joao, X).
X = maria ;         % só os filhos de joao
X = pedro.

?- pai(joao, X), mulher(X).
X = maria.          % maria serve; em pedro, mulher(pedro) FALHA
                    % e o Prolog volta sozinho para outra cláusula de pai
```

Moral: na consulta **simples**, ele só continua se você digitar `;`. Na **composta**, quando o
objetivo da direita falha, o Prolog **desfaz** as atações e **retoma** o da esquerda — sozinho.

> Para acompanhar ao vivo: digite `?- trace.` antes e `?- notrace.` + `?- nodebug.` no fim.

## 4. Consultas compostas

Consultas simples podem ser combinadas em **consultas compostas** com o operador `,/2`
(**e** lógico):

```prolog
% ilustração de sintaxe (nomes genéricos; não executável)
?- query1(a1, ..., ak), query2(b1, ..., br), ..., queryN(z1, ..., zs).
```

- Se a **mesma variável** aparece em mais de um predicado, ela deve assumir o **mesmo valor**
  em todos.
- O **escopo** de uma variável lógica é a consulta (simples ou composta).

```prolog
% fatos em codes/capital.pl (salve só as cláusulas, sem as linhas ?-, e consulte)
?- cidade(X, mt), capital(X).
?- cidade(X, Y), regiao(centro_oeste, Y), capital(X).
```

### Fluxo de controle de consultas compostas

- O backtracking tenta unificar os objetivos **da esquerda para a direita**.
- Termina com **sucesso** apenas se sai pela porta `exit` do predicado **mais à direita**.
- Se uma consulta sai por `redo`, apenas as variáveis **atadas no predicado da porta** são
  desatadas (as dos predicados à esquerda permanecem atadas).
- Se a consulta **falha** para algum predicado, ela falha **como um todo**.
- O `;` força uma reentrada no **último** predicado pela porta `redo`.

## 5. Predicados extra-lógicos

São **predicados pré-definidos** em Prolog, para os quais **não há cláusulas**. Quando um
objetivo unifica com um deles, o interpretador chama uma **rotina interna** que executa
tarefas **fora do contexto da prova de teoremas** (ex.: escrever no terminal).

Eles respondem tanto na porta `call` quanto na `redo`. A resposta na porta `redo` é chamada
**comportamento no backtracking**.

| Predicado | Resposta na `call` | Resposta na `redo` |
|---|---|---|
| `write/1` | Casa com qualquer padrão; como efeito colateral, escreve o argumento no console | **Sempre falha** |
| `nl/0` | Sempre bem-sucedido; inicia uma nova linha | Sempre falha |
| `tab/1` | Avança o cursor N espaços | Sempre falha |
| `fail/0` | Sempre falha (equivale a `false/0`) | — |

> O **comportamento no `redo`** de `write/1` (sempre falha) é o que permite gerar uma saída
> repetida com força bruta. Ex.: o predicado abaixo imprime **todos** os quadriláteros que
> têm lados iguais e ângulos retos, sem interação:

```prolog
% fatos em codes/quadrilaterals.pl (salve só as cláusulas, sem as linhas ?-, e consulte)
?- quadrilateral(X), equal_sides(X), write(X), nl, fail.
```

O `fail/0` força o backtracking a continuar, gerando cada solução; a cláusula final `unb_report.`
evita que o resultado geral seja falso.

## 6. Condicionais

O predicado extra-lógico `->/2` habilita condicionais em Prolog. Sintaxes:

```prolog
If -> Then
If -> Then ; Else
```

- Se `If` corresponder a um predicado **verdadeiro**, o fluxo segue para `Then`.
- No segundo caso, se `If` for **falso**, o fluxo segue para `Else`.

Exemplo — gerar a **tabela-verdade** de um conectivo binário:

```prolog
% cláusulas em codes/truth_table.pl (salve sem as linhas ?-, que são exemplos, e consulte)
:- meta_predicate execute_goal(2).

execute_goal(Op, X, Y) :-
    (call(Op, X, Y) -> writeln(true) ; writeln(false)).

truth_table(Op, Symbol) :-
    bool(X), bool(Y),
    write(X), write(' '), write(Symbol), write(' '), write(Y), write(' = '),
    execute_goal(Op, X, Y), fail.
truth_table(_, _).

?- truth_table(and, '&').
true & true = true
true & false = false
false & true = false
false & false = false
true.
```

## 7. Rastreamento (trace)

- `trace/0` permite rastrear o fluxo de controle — todas as consultas subsequentes são
  rastreadas.
- `creep` avança para o próximo passo da execução (no SWI-Prolog, pela barra de espaço).
- `notrace/0` desativa o rastreamento; em seguida, consulte `nodebug/0`.
