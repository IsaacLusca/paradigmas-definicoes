## 1. Contexto / Motivação

A unificação é o **motor** do Prolog: é o mecanismo de casamento de padrões que responde a
uma consulta. Nas aulas anteriores você viu uma versão simplificada (só fatos). Aqui você
entende o processo **completo**, os predicados que o tratam (`=/2`, `\=/2`), e as **listas**
— a estrutura de dados mais importante do paradigma lógico — além dos **meta-predicados**
que operam sobre listas (`maplist`, `include`/`exclude`, `foldl`).

---

## 2. Processos de unificação

| Elementos | Comportamento |
|---|---|
| **Variável e termo** | Uma variável unifica com **qualquer termo** (inclusive outras variáveis). O valor do termo é **atado** à variável. |
| **Primitivo e primitivo** | Dois termos primitivos (átomos/números) unificam apenas se são **idênticos**. |
| **Estrutura e estrutura** | Unificam se têm **mesmo construtor**, **mesma aridade** e cada par de argumentos correspondentes unifica. |

---

## 3. Predicados que tratam da unificação

- **`=/2`** — bem-sucedido se ambos os argumentos **unificam**; falha, caso contrário.
- **`\=/2`** — verdadeiro se os argumentos **não unificam**.
- **`_`** (variável anônima) — *wildcard*: casa com qualquer termo e **não é atada** a valor.

```prolog
% nativo: não precisa carregar arquivo
?- a = a.
true.
?- a = b.
false.
?- x(y, z(i, j)) = x(y, z(i, j)).
true.
?- x(y, z(i, j)) = x(y, z(j, i)).
false.
?- 2 + 2 = 4.
false.          % unificação é sintática: 2+2 é um termo, não o número 4
```

### Variável × primitivo

```prolog
% nativo: não precisa carregar arquivo
?- X = a.
X = a.
?- 2 = Y.
Y = 2.
?- f(x, y) = f(X, y).
X = x.
?- f(x, y) = f(X, Y).
X = x.
Y = y.
```

### Variável × variável

```prolog
% nativo: não precisa carregar arquivo
?- A = B.
A = B.
?- f(X, y) = f(Z, y).
X = Z.
?- X = Y, Y = teste.
X = Y, Y = teste.
?- X = Y, a(Z) = a(Y), X = teste.
X = Y, Y = Z, Z = teste.
```

## 4. Listas em Prolog

Uma **lista** é uma coleção de termos de **quaisquer tipos**. Sintaxe:

```prolog
[term1, term2, ..., termN]
```

- A lista **vazia** (também `nil`) é `[]`.
- A unificação trata listas como uma estrutura de dados.

```prolog
% nativo: o asserta cria o fato f/2 na hora; não precisa carregar arquivo
?- asserta(f([a, b, c], d)).
true.
?- f(X, d).
X = [a, b, c].
?- [_, X, _] = [1, 2, 3].
X = 2.
```

### Casamento de padrão: `[X | Y]`

A notação `[X | Y]` ata `X` ao **primeiro elemento** (*head*) e `Y` à lista dos **demais**
(*tail*):

```prolog
% nativo: não precisa carregar arquivo
?- [H|T] = [1, 2, 3, 4, 5].
H = 1,
T = [2, 3, 4, 5].

?- [H|T] = [].
false.          % lista vazia não tem head/tail

?- [A, B | T] = [1, 2, 3, 4, 5].
A = 1, B = 2, T = [3, 4, 5].
```

### Listas e predicados

Embora tenha sintaxe especial, uma lista é, de fato, o predicado de **dois argumentos**
`'[|]'/2` (primeiro = head, segundo = tail):

```prolog
% nativo: não precisa carregar arquivo
?- L = '[|]'(1, '[|]'(2, '[|]'(3, []))).
L = [1, 2, 3].
```

A estrutura da lista é adequada para **rotinas recursivas** — ex. `length/2`:

```prolog
length_([_|T], X) :- length_(T, NewX), X is NewX + 1.
length_([], 0).
```

## 5. Predicados que agem em listas

### Teste de pertinência — `member/2`

Determina se um termo é membro da lista:

```prolog
% cláusulas em codes/member.pl: ?- consult('codes/member.pl').
member_(H, [H|_]).
member_(X, [_|T]) :- member_(X, T).
```

- 1ª cláusula: o elemento é o **head** da lista.
- 2ª cláusula (recursiva): procura o elemento no **tail**.
- Ambas falham em listas vazias, pois `[]` e `[H|T]` não unificam.

### Concatenação — `append/3`

Anexa o 2º argumento ao 1º, unificando o resultado com o 3º:

```prolog
% nativo: append/3 é da biblioteca, não precisa carregar arquivo
?- append([1, 2], [3, 4, 5], X).
X = [1, 2, 3, 4, 5].
```

Implementação:

```prolog
% cláusulas em codes/append_impl.pl (ATENÇÃO: tem bug — [H, T2] deveria ser [H|T2])
append([], X, X).
append([H|T1], X, [H, T2]) :- append(T1, X, T2).
```

> `append/3` também **decompõe** listas:
> `?- append(X, Y, [1, 2, 3, 4]).` gera todas as divisões possíveis.

### Listas e fatos

Declarar fatos a partir de uma lista com `assertz/1` no head, recursivamente; e o processo
inverso com `findall/3`:

```prolog
% cláusulas em codes/list_to_facts.pl: ?- consult('codes/list_to_facts.pl').
list_to_facts([]).
list_to_facts([H|T]) :- assertz(H), list_to_facts(T).
```

```prolog
% nativo (findall/3), mas precisa dos fatos f/1 e g/1 (ver list_to_facts acima)
?- findall(X, f(X) ; g(X), L).
L = [1, 3].
```

- `findall/3`: 1º arg = **padrão** para os termos; 2º = **objetivo**; 3º = **lista resultante**.

## 6. Meta-predicados

### `maplist/N`

Retorna verdadeiro se o objetivo `Goal` é bem-sucedido para todas as N-tuplas de elementos
correspondentes das listas indicadas. SWI-Prolog disponibiliza versões para N ∈ [2, 5].

```prolog
% maplist é nativo (biblioteca); celsius_fahrenheit/2 está em codes/celsius.pl (aula 04)
?- maplist(celsius_fahrenheit, [-1, 100, 40], F).
F = [30.2, 212, 104].
```

Exemplo — subconjuntos e replicação:

```prolog
% cláusulas em codes/maplist_examples_2.pl: ?- consult('codes/maplist_examples_2.pl').
subset(N, S) :-
    length(S, N),
    maplist(between(0, 1), S).

replicate(N, Value, L) :-
    length(L, N),
    maplist(=(Value), L).
```

### `include/3` e `exclude/3`

- `include(Goal, List, Filtered)` — filtra os elementos para os quais o objetivo é
  **verdadeiro**.
- `exclude/3` — similar, mantém os elementos para os quais o objetivo **falha**.
- Parâmetros na mesma ordem do `include/3`.

```prolog
% cláusulas em codes/include.pl (salve sem as linhas ?-): ?- consult('codes/include.pl').
is_odd(X) :- X mod 2 =\= 0.

odds(L, Odds) :- include(is_odd, L, Odds).
evens(L, Evens) :- exclude(is_odd, L, Evens).

?- numlist(1, 5, L), odds(L, Odds), evens(L, Evens).
L = [1, 2, 3, 4, 5],
Odds = [1, 3, 5],
Evens = [2, 4].
```

### `foldl/N`

"Dobra" os elementos de $m\in[1,4]$ listas por meio do objetivo `Goal/(m+1)`, onde `V0` é o
**valor inicial**. `scanl/N` é similar, mantendo os **resultados parciais**.

```prolog
% cláusulas em codes/summation.pl: ?- consult('codes/summation.pl').
summation(A, B, Sum) :- numlist(A, B, L), foldl(plus, L, 0, Sum).

multiply(A, B, C) :- C is A * B.

factorial(N, Fact) :- numlist(1, N, L), foldl(multiply, L, 1, Fact).
```

> **Atenção a dois comportamentos:**
> - **`append_impl.pl` tem um BUG** (defeito no material): usa `[H, T2]` (lista de 2 elementos)
>   em vez de `[H|T2]`. Resultado: `?- append([1, 2], [3, 4, 5], X).` → `X = [1,[2,[3,4,5]]]`
>   (o certo seria `[1,2,3,4,5]`). O `append/3` **da biblioteca** funciona:
>   `?- append(X, Y, [1, 2, 3, 4]).` gera as 5 divisões.
> - **`maplist_examples.pl`:** a ordem de `is_multiple/2` é `is_multiple(X, Y) :- X mod Y =:= 0`,
>   então `common_multiple(12, [3, 4, 6])` → `true`, mas `common_multiple(3, [6, 9, 12])` → `false`.

> **Transcrições** (não carregam; rode à mão): `eq.pl`, `primitivo.pl`, `variables.pl`,
> `compostas.pl`, `lists.pl`, `head_and_tail.pl`, `cons.pl`, `append.pl`, `append_example.pl`,
> `findall.pl`, `maplist.pl`, `foldl.pl`. (`foldl.pl`/`maplist.pl` são pseudo-código com `...`.)
> Ex.: `?- [H|T] = [1, 2, 3], [A|B] = [6].` → `H = 1, T = [2,3], A = 6, B = [].`
