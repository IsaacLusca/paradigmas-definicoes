## 2. Termos primitivos e axiomas

### O problema da regressão infinita de definições

Toda definição usa palavras, e cada palavra usada na definição precisaria, por sua vez, ser
definida. Exemplo — "conjunção":

> *"a ∧ b é verdadeiro quando a e b são ambos verdadeiros"*

- O que é "verdadeiro"? → precisaria de outra definição.
- O que é "proposição"? → de outra...
- O que é "afirmação", "sentença", "significado"? → e assim por diante.

Cada definição **ramifica** em novas definições, gerando um ciclo infinito: ou voltamos
sempre ao mesmo ponto (definições circulares), ou nunca chegamos ao fim
(*regressão infinita*). Formalizar a lógica exige **parar o ciclo em algum lugar** —
um "limite" onde o vocabulário e as regras são **aceitos sem definição nem prova**.

### Termos primitivos — o vocabulário aceito sem definição - Base da programação lógica

São os **nomes fundamentais** do sistema: não são definidos, são *dados*. Qualquer outra
definição é construída em cima deles.

| Termo primitivo | Papel no sistema |
|---|---|
| **Proposição** | A unidade mínima que pode ser julgada: algo que afirma um fato e pode ser avaliado como verdadeiro ou falso ("está chovendo", "2 + 2 = 4"). |
| **Verdadeiro** | Um dos dois valores lógicos possíveis de uma proposição. |
| **Falso** | O outro valor lógico possível. |

Ex.: a proposição "2 + 2 = 4" **é** verdadeira — não precisamos definir o que é
"verdadeiro" para usá-lo; tomamos o termo como ponto de partida.

### Axiomas — as regras aceitas sem prova

São **proposições que não se provam**: são assumidas como verdadeiras para servir de
alicerce. Toda dedução do sistema parte delas; provar um axioma exigiria outros axiomas
— e cairíamos de novo no ciclo.

| Axioma | Enunciado |
|---|---|
| **Princípio do terceiro excluído** | Toda proposição é verdadeira **ou** falsa — não existe uma terceira possibilidade (*tertium non datur*). |
| **Princípio da não-contradição** | Uma proposição **não pode ser** verdadeira e falsa ao mesmo tempo. |

Juntos, os dois axiomas garantem que o universo de valores lógicos é exatamente
{verdadeiro, falso}: toda proposição recebe exatamente um dos dois valores — pelo menos um
(terceiro excluído) e no máximo um (não-contradição). É esse pressuposto que torna a lógica
booleana possível (e que, mais adiante, o Prolog explora com `true/0` e `false/0`).

### Analogia: a geometria de Euclides

O mesmo padrão aparece na geometria clássica:

- **Primitivos:** ponto, reta e plano — não têm definição formal, são intuitivos.
- **Axiomas (postulados):** "por dois pontos distintos passa uma única reta" — aceitos
  sem prova.
- **Derivados:** teoremas como o de Pitágoras, **provados** a partir dos primitivos e axiomas.

Na lógica proposicional a estrutura é análoga: primitivos + axiomas são o "térreo" do
edifício; conectivos, fatos, regras e teoremas são os andares construídos em cima.

### Resumo

| Termos primitivos (vocabulário dado) | Axiomas (verdades assumidas) |
|---|---|
| Proposição | Princípio do **terceiro excluído** |
| Verdadeiro | Princípio da **não-contradição** |
| Falso | |

## 3. Conectivos da lógica proposicional booleana

> Conectivos têm **várias notações** conforme a área (matemática, programação, circuitos).
> Abaixo, a tabela com os símbolos mais comuns de cada versão.

| Operação | Símbolos (versões) | Leitura | Definição |
|---|---|---|---|
| **Negação** | $\lnot a$ · $\sim a$ · $\bar{a}$ · `!a` · `NOT a` | não $a$ | Inverte o valor lógico de $a$ |
| **Disjunção (OR)** | $a \vee b$ · $a \mid b$ · $a + b$ · `a \|\| b` · `a or b` | $a$ ou $b$ | Falso apenas se $a$ e $b$ são ambos falsos |
| **Conjunção (AND)** | $a \land b$ · $a \& b$ · $a \cdot b$ · `a && b` · `a and b` | $a$ e $b$ | Verdadeiro apenas se $a$ e $b$ são ambos verdadeiros |
| **Condicional (→)** | $a \to b$ · $a \Rightarrow b$ · $a \supset b$ | se $a$, então $b$ | Falso apenas se $a$ é verdadeiro e $b$ é falso |
| **Bicondicional (↔)** | $a \leftrightarrow b$ · $a \iff b$ · $a \equiv b$ · `a == b` | $a$ se, e somente se, $b$ | Verdadeiro se ambos têm o mesmo valor lógico |

### Notas sobre as versões

- **Negação:** $\bar{a}$ (barra sobre a letra) é comum em álgebra booleana e circuitos;
  `!a` em C/Java; `NOT a` em SQL/Assembly; em Prolog é o predicado `\+/1`.
- **OR/AND:** $+$ e $\cdot$ vêm da álgebra booleana (de Boole); `||`/`&&` em C/Java;
  `or`/`and` em Python; `\/`/`,` são os operadores de controle do Prolog (seção 6).
- **Condicional:** $\Rightarrow$ e $\supset$ aparecem em textos de lógica; o "se...então"
  é o mesmo conectivo.
- **Bicondicional:** $\equiv$ é o símbolo de equivalência lógica; `==` em linguagens
  imperativas compara valores (comportamento análogo ao "mesmo valor lógico").

### Em Python (para comparar)

```python
a = True; b = False
not a          # False          (negação)
a or b         # True           (disjunção)
a and b        # False          (conjunção)
a == b         # False          (bicondicional sobre valores)
# Python não tem operador direto para a → b (condicional):
# implementa-se como: (not a) or b
```

## 4. Valores lógicos em Prolog -PROgramming in LOGic

- Verdadeiro e falso são implementados pelos predicados `true/0` e `false/0`.

```prolog
% true/0 e false/0 são nativos: não precisa carregar arquivo
?- true.
true.

?- false.
false.
```

- **Prolog distingue maiúsculas de minúsculas**:

```prolog
% nativo: não precisa carregar arquivo
?- True.
% ... 1,000,000 ............ 10,000,000 years later
%       >> 42 << (last release gives the question)
```

(`True` é uma variável; `true` é o predicado.)

## 5. Fatos

- Fatos são os predicados mais simples do Prolog e correspondem a **proposições verdadeiras**.
- Sintaxe: `pred(arg1, arg2, ..., argN).`
  - `pred` = **nome** do predicado
  - `arg1..argN` = **argumentos**
  - `N` = **aridade** (número de argumentos)
  - `.` = **terminador** (ponto final obrigatório)

**Conectivos como fatos** (proposições não declaradas são consideradas falsas — *closed world*):

```prolog
and(true, true).

or(true, true).
or(true, false).
or(false, true).

not(false).
```

### Declarando e consultando

- Fatos vivem em arquivos `.pl`, lidos pelo interpretador.
- `$ prolog -s source.pl` — carrega na inicialização.
- `consult/1` e `reconsult/1` — carregar/recarregar em sessão interativa.
- **Programas = consultas** na base de fatos (resposta `true`/`false`):

```prolog
?- consult('codes/conectivos.pl').
true.

?- and(true, false).
false.

?- or(false, true).
true.

?- not(true).
false.
```

## 6. Proposições compostas

### Predicado não é função — nunca retorna nada!

Antes de tudo, um ponto central: **predicado ≠ função**. Em Prolog, um predicado **nunca
retorna um valor**. Uma função (C, Python, etc.) *computa* e *devolve* um resultado que
pode ser usado como dado de outra expressão. Um predicado apenas **é provado verdadeiro
ou falso** pelo interpretador — a resposta `true`/`false` é o *veredito* da prova, não um
valor que volta para ser combinado.

É por isso que, se você tenta usar `and`/`or`/`not` como se fossem funções aninhadas:

```prolog
?- consult('codes/conectivos.pl').   % and/2 e or/2 são fatos deste arquivo
true.
?- and(or(true, false), true).
false.        % falha por unificação, apesar de (F ∨ V) ∧ V ser verdadeira
```

...o Prolog **não avalia** `or(true, false)` para depois passar o resultado a `and/2`.
Ele tenta **unificar** a consulta `and(or(true, false), true)` contra os fatos da base —
e nenhum fato tem como primeiro argumento o termo composto `or(true, false)` (que nem é
um valor lógico: é um termo). Não existe "resultado de `or(...)`" para combinar porque
**`or/2` nunca retornou nada** — predicado não retorna, apenas prova ou falha.

**Em resumo:** proposições compostas não funcionam com fatos porque
1. predicado não é função (não há valor de retorno para aninhar);
2. a unificação compara a consulta inteira, termo por termo, com os fatos;
3. um termo composto como `or(true, false)` não casa com nenhum fato declarado.

A linguagem resolve isso com **predicados de controle** — que são traduzidos pelo
compilador (seção abaixo), não provados como fatos:

```prolog
% nativo: não precisa carregar arquivo
?- (false ; true), true.
true.
```

### Predicados de controle

São predicados que implementam estruturas de controle e, em geral, são traduzidos pelo
compilador (operadores infixados):

| Predicado                     | Operação               | Observação                                                                                                        |
| ----------------------------- | ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `,/2`                         | conjunção (e)          | **nativo**; op 1000 xfy                                                                                           |
| `;/2`                         | disjunção (ou)         | **nativo**; op 1100 xfy; usar parênteses é fortemente recomendado                                                 |
| `->/2`                        | if-then (se...então)   | **nativo**; op 1050 xfy. **Não é implicação material**: $a \to b$ é `\+ a ; b`. Comita na condição (extra-lógico) |
| `\+/1`                        | negação (não)          | **nativo**; op 900 fy; verdadeiro apenas quando não há prova (negação por falha)                                  |
| `true/0`, `fail/0`, `false/0` | constantes de controle | **nativos** (predicados)                                                                                          |
| `!/0`                         | cut                    | **nativo**; poda pontos de escolha                                                                                |

> **Nativo × definido pelo usuário:** `,` `;` `->` `\+` e `true/fail/false/!` são **nativos** do
> Prolog (o compilador traduz; não ficam na base). Já `and/2`, `or/2`, `not/2` em
> [`conectivos.pl`](codes/conectivos.pl) são **fatos definidos pelo usuário** (mundo fechado) e
> só "imitam" o conectivo porque declaramos quais combinações são verdadeiras.

```prolog
% nativo: não precisa carregar arquivo
?- (false ; true), true.
true.
```

### Proposições compostas: consultas, resultados e o que mais cai

Combinar conectivos é combinar **objetivos** com os predicados de controle. Entradas e saídas
esperadas no listener:

| Consulta | Resultado | Conectivo |
|---|---|---|
| `?- true, true.` | `true` | conjunção (`∧`) |
| `?- true, false.` | `false` | conjunção |
| `?- false ; true.` | `true` | disjunção (`∨`) |
| `?- false ; false.` | `false` | disjunção |
| `?- \+ true.` | `false` | negação (`¬`) |
| `?- \+ false.` | `true` | negação |
| `?- ((false ; true), true).` | `true` | precedência: `(F ∨ V) ∧ V` |
| `?- and(or(true, false), true).` | `false` | **predicado ≠ função** (não avalia aninhado) |

Mais casos dos **operadores de controle** (mesmo formato do listener):

```prolog
% só operadores nativos de controle: não precisa carregar arquivo
% --- constantes de controle ---
?- true.
true.
?- false.
false.
?- fail.
false.

% --- conjuncao  ,  (a e b) ---
?- true, true.
true.
?- true, false.
false.
?- false, true.
false.
?- false, false.
false.

% --- disjuncao  ;  (a ou b) ---
?- true ; true.
true.
?- true ; false.
true.
?- false ; true.
true.
?- false ; false.
false.

% --- negacao  \+  (nao a) ---
?- \+ true.
false.
?- \+ false.
true.
?- \+ fail.
true.
?- \+ (true, false).
true.
?- \+ (true, true).
false.

% --- condicional  ->  (se a entao b) ---
?- true -> true.
true.
?- true -> false.
false.
?- false -> true.
false.
?- (true -> false ; true).
false.        % o '->' COMITA: nao cai no 'else'
?- (false -> true ; false).
false.        % condicao falsa: usa o 'else'

% --- misturando (precedencia) ---
?- (false ; true), true.
true.
?- (true ; false), false.
false.
?- \+ true ; false.
false.        % = (\+ true) ; false
?- (false ; true) -> true.
true.
?- true ; false, false.
true.         % = true ; (false, false)
```

#### Pegadinha: `(If -> Then ; Else)` — o `->` **comita**

`(Cond -> Then ; Else)` **não** é uma disjunção comum: o `;` faz parte do if-then-else.

| Situação | O que acontece |
|---|---|
| `Cond` **sucede** | o Prolog **comita** na 1ª solução de `Cond` e avalia `Then`; se `Then` **falhar**, **todo o construto falha** (o `Else` **não** é tentado) |
| `Cond` **falha** (nenhuma solução) | só então o `Else` é avaliado |

```prolog
% nativo: não precisa carregar arquivo
?- (true -> false ; true).
false.        % true sucede → comita → false falha → FALHA (else NAO roda)
?- (fail -> true ; true).
true.         % a condicao falha → vai para o else
?- (true -> fail ; true).
false.        % de novo: comita, o then falha, o else nao roda
```

Leitura lógica do if-then-else: $(Cond \land Then) \lor (\neg Cond \land Else)$. Com
`Cond=true`, `Then=false`, `Else=true` → $(V \land F) \lor (F \land V)$ = **false**. O `true` que
parece "óbvio" seria a fórmula $(Cond \to Then) \lor Else$ — **outra** fórmula.

O commit também **poda alternativas da condição**:

```prolog
% nativo (member/2 e writeln/1 são da biblioteca): não precisa carregar arquivo
?- ( member(X, [1,2,3]) -> writeln(X) ; writeln(none) ).
1
true.         % so o 1o X: nao volta para X=2, X=3
```

Para ter a disjunção "de verdade" (sem commit), isole com `call/1`:

```prolog
% nativo: não precisa carregar arquivo
?- ( call((true -> false)) ; true ).
true.         % agora o ';' e disjuncao comum
```

**O que mais cai (base: Prova 1 real — 4BAE41):**

| Item | Como apareceu |
|---|---|
| **Nº de linhas da tabela-verdade** de uma proposição composta | Q11: $(p \lor (q \land p)) \land (\sim p \lor (p \land q))$ → só $p,q$ → $2^2 = \mathbf{004}$ |
| **Identificar o conectivo** pelo símbolo | Q1: bicondicional = **↔** |
| **Predicado ↔ conectivo** em base fechada | Q2: `op(true, true).` (único fato) → **conjunção** |
| **Controle × aninhamento** | `(false ; true), true` → `true` × `and(or(...), ...)` → `false` |

> Os **simulados** (feitos com IA) também cobram XOR/NAND/NOR e a regra "falso/verdadeiro
> apenas quando...", mas **isso não apareceu na Prova 1 real**; trate como possibilidade
> extra, não como prioridade.

### Ordem de precedência dos operadores

Todo operador Prolog tem uma **precedência** (inteiro entre 0 e 1200) e um **tipo** de
associatividade. Regra de ouro: **quanto menor o número, maior a precedência** — o
operador de menor número "liga mais forte" e agrupa seus operandos antes.

| Precedência | Operador | Tipo | Significado |
|---|---|---|---|
| 1200 | `:-` · `-->` | xfx | regra / implicação |
| 1100 | `;` | xfy | **disjunção** (ou) |
| 1050 | `->` | xfy | if-then |
| 1000 | `,` | xfy | **conjunção** (e) |
| 900 | `\+` | fy | **negação** (não) |
| 700 | `=` `==` `\==` `<` `>` `=<` `>=` `=:=` `=\=` `is` | xfx | unificação, comparação, avaliação |
| 500 | `+` `-` | yfx | soma, subtração |
| 400 | `*` `/` `//` `mod` | yfx | multiplicação, divisão, resto |
| 200 | `^` | xfy | potência (associa à direita) |
| 200 | `-` (unário) `+` (unário) | fy | sinal |
| 0 | — | — | **apaga** a declaração do operador |

**Notação do tipo (`f`, `x`, `y`) — é padrão do Prolog.** O nome do tipo descreve a **forma**
onde está o operador (`f`) e a **força** que cada argumento pode ter:

| Letra | Significado                                                                                                                                   |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `f`   | posição do **operador** (functor). Em `xfy` o `f` fica no meio: `a Op b`; em `fy`/`fx`, à esquerda: `Op a`                                    |
| `x`   | argumento com precedência **estritamente menor** que a do operador (`< P`) → aquele lado **não** aceita o **mesmo** operador (lado "travado") |
| `y`   | argumento com precedência **menor ou igual** (`≤ P`) → aquele lado **aceita** o mesmo operador (lado "associativo")                           |

| Tipo | Forma | Associatividade | Exemplos (precedência) |
|---|---|---|---|
| `xfx` | `a f b` | **nenhuma** (não associa) | `=` `==` `<` `=:=` (700) — `a = b = c` é **erro de sintaxe** |
| `xfy` | `a f b` | **à direita** | `,` `;` `->` `:-` `^` (1000/1100/1050/1200/200) |
| `yfx` | `a f b` | **à esquerda** | `+` `-` `*` `/` `//` `mod` (500/400) |
| `fy`  | `f a` | prefixo, **pode repetir** | `\+` (900), `-` unário (200) |
| `fx`  | `f a` | prefixo, **não repete** | `:-` diretiva (1200) |
| `yf` / `xf` | `a f` | pós-fixado (raro) | — |

Consequências:
- `a - b - c` (yfx) = `(a - b) - c` — a aritmética usual;
- `a , b , c` (xfy) = `a , (b , c)`; e `2 ^ 3 ^ 2` (xfy) = `2 ^ (3 ^ 2) = 512`;
- `a = b = c` (xfx) = **erro de sintaxe** → compare em cadeia com parênteses: `(a = b), (b = c)`.

**Por que usar parênteses com `;`:** como a conjunção (1000) tem **maior precedência**
que a disjunção (1100), `a ; b , c` é lido como `a ; (b , c)`, e não como
`(a ; b) , c`. Para expressar `(F ∨ V) ∧ V` em Prolog, os parênteses em
`(false ; true), true` são obrigatórios — sem eles a leitura seria
`false ; (true, true)`, outra proposição.

### Associatividade na prática (entradas e saídas)

```prolog
% is/2, current_op/3 e =:= são nativos: não precisa carregar arquivo
?- Y is 10 - 2 - 3.
Y = 5.                          % yfx: (10 - 2) - 3

?- Y is 2 ^ 3 ^ 2.
Y = 512.                        % xfy: 2 ^ (3 ^ 2)

?- 1 =:= 2 =:= 3.
ERROR: Syntax error             % xfx: não associa

?- current_op(P, T, '+').
P = 500, T = yfx ;
P = 200, T = fy.                % '+' binário (yfx) e unário (fy)
```

> Com **letras** (`a - b - c`) não dá para executar: `-` só funciona como predicado no contexto
> aritmético (`is/2`). Para ver o agrupamento de um termo qualquer:
> `?- X = (a - b - c), write_canonical(X).` → `X = -(-(a,b),c)`.

### Precedência × conectivos (tabela associada + exemplos)

| Prec | Operador | Regra lógica | Exemplo |
|---|---|---|---|
| 900 | `\+` | **não a** | `\+ true` → `false` · `\+ fail` → `true` |
| 1000 | `,` | **a e b** | `true, true` → `true` |
| 1050 | `->` | **se a então b** | `true -> true` → `true` |
| 1100 | `;` | **a ou b** | `false ; true` → `true` |
| 1200 | `:-` | regra (`cabeça :- corpo`) | — |

Ordem de força: `\+` > `,` > `->` > `;`. Pares com resultados reais:

| Sem parênteses | Como o Prolog agrupa | Result. | Com parênteses | Result. |
|---|---|---|---|---|
| `fail, true ; true` | `(fail, true) ; true` | `true` | `fail, (true ; true)` | `false` |
| `true ; fail -> fail` | `true ; (fail -> fail)` | `true` | `(true ; fail) -> fail` | `false` |
| `\+ true, false` | `(\+ true), false` | `false` | `\+ (true, false)` | `true` |

> Só as constantes de controle (`true`, `false`, `fail`) — não precisa definir nada.

### O operador `:-` (regra × diretiva) e `?-`

`:-` (precedência **1200**) é **nativo** e tem **dois papéis** (mesmo símbolo, tipos diferentes):

| Forma | Tipo | Papel | Exemplo |
|---|---|---|---|
| `cabeça :- corpo` | xfx | **regra**: "cabeça **se** corpo" — o corpo **implica** a cabeça (`corpo → cabeça`) | `par(X) :- 0 =:= X mod 2.` |
| `:- Objetivo.` | fx | **diretiva**: executada ao **carregar** o arquivo | `:- op(...)`, `:- dynamic p/1`, `:- use_module(...)` |

E `?-` (fx, 1200) é o operador da **consulta** no listener. Os **dois papéis** do `:-` aparecem no
`current_op/3` (nativo — não precisa carregar arquivo):

```prolog
% nativo: não precisa carregar arquivo
?- current_op(P, T, ':-').
P = 1200, T = fx ;        % diretiva: :- Objetivo.
P = 1200, T = xfx.        % regra:     cabeça :- corpo
```

Uma regra no formato acima (texto do arquivo, não executável aqui):
`par(X) :- 0 =:= X mod 2.` — carga via `?- consult('codes/rules.pl').` na
[aula 02](../aula_02_logica_de_primeira_ordem/02.aula_02_logica_de_primeira_ordem.md) e consulta
`?- unb(ana).` → `true.`

> Direção da implicação: `cabeça :- corpo` ≡ `corpo → cabeça` (seta invertida). Um **fato** `p.`
> é equivalente a `p :- true.`; e `p :- fail.` é um predicado que **sempre falha**.

**Declarando e consultando operadores:**

```prolog
% nativos: não precisa carregar arquivo
?- op(700, xfx, meu_op).                 % declara (ou redefine) um operador
true.
?- current_op(Precedence, Type, meu_op). % consulta operadores definidos
Precedence = 700, Type = xfx.
```

## 8. Bônus: `True` e `False` em Python são objetos — o que isso significa?

### A ideia por trás

Em Python, **tudo é objeto** — inclusive valores lógicos. Quando você escreve `True` ou
`False`, está se referindo a **dois objetos concretos que existem na memória**, cada um
com um tipo, uma identidade e até métodos. Eles não são apenas "palavras da linguagem"
(sintaxe), são **dados** que podem ser guardados, passados e manipulados como qualquer
outro valor.

`True` e `False` são as **únicas duas instâncias** da classe `bool` (a classe `bool` é um
*singleton* duplo: não existe um terceiro booleano). Além disso, `bool` é **subclasse de
`int`** — herança que dá comportamento inesperado a quem vem de outras linguagens.

### O que ser objeto permite fazer

```python
type(True)             # <class 'bool'>  -> tem um tipo
isinstance(True, int)  # True            -> bool herda de int
True + True            # 2               -> herança de int em ação
True.bit_length()      # 1               -> tem métodos

x = True
y = True
x is y                 # True  -> mesmo objeto na memória (singleton)
x is True              # True  -> identidade de objeto
True == 1              # True  -> igual em valor...
True is 1              # False -> ...mas objetos diferentes!

valores = [True, False, True]      # pode ir em listas
d = {True: "sim", False: "não"}    # pode ser chave de dicionário
def f(a, b): return a and b        # pode ser argumento/retorno de função
```

### O contraste com Prolog (o porquê da pergunta)

Em Prolog, `true` e `false` **não são objetos nem dados** — são **predicados** (`true/0`,
`false/0`): *ações* que você pergunta ao interpretador. Eles só existem no momento de uma
**consulta**, como resultado de derivação/unificação. Não dá para "guardar" `true` numa
variável ou passá-lo como dado de um programa Prolog — ele é o resultado de uma execução,
não um valor manipulável.

| Aspecto | Python (`True`/`False`) | Prolog (`true`/`false`) |
|---|---|---|
| Natureza | **Objetos** (dados) — instâncias de `bool` | **Predicados** — `true/0`, `false/0` |
| O que são | Valores que existem na memória | Resultados de consultas ao interpretador |
| Podem ser armazenados? | Sim (variável, lista, dict, chave) | Não — são respostas, não dados |
| Têm tipo/identidade? | Sim (`bool`, singleton, herda de `int`) | Não — apenas nome+aridade |
| Papel | *Citizen of first class* (dado manipulável) | Verificação dentro de uma derivação |
| Caso de uso típico | `if x:` em expressões e estruturas | `?- true.` como alvo de consulta |

**Resumo:** dizer que "True/False em Python são objetos" significa que, naquele
paradigma (imperativo/POO), o valor lógico é tratado como **dado de primeira classe** —
algo que existe, tem tipo, e pode circular pelo programa. No Prolog (paradigma lógico),
verdadeiro/falso não são coisas que circulam: são o **veredito** que o interpretador
emite ao tentar provar uma consulta.
